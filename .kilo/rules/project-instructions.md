Project Instructions – Pebble Watchface
1. Project Specification

The file docs/WATCHFACE_SPECIFICATION.md is the authoritative specification for this project.

You MUST:

Read and understand this document before implementing new functionality.
Treat its functional requirements and implementation decisions as the source of truth.
Follow the described architecture, data structures, and design decisions.
Avoid introducing functionality that conflicts with the specification.
Never silently change an existing requirement or design decision.
2. Development Guidelines
Before making changes, inspect the existing implementation.
Understand how the proposed changes fit into the existing architecture.
Reuse existing functions and components wherever possible.
Avoid unnecessary refactoring or architectural changes.
Preserve existing functionality unless explicitly instructed otherwise.
Follow the Pebble SDK conventions and APIs appropriate to this project.
3. Implementation Workflow

For every coding task:

Consult the project specification.
Inspect the relevant source files.
Identify the files and components that need modification.
Check that the proposed implementation is consistent with the specification.
Implement the changes.
Check for compilation errors and regressions.
Explain what was changed and identify any deviations from the specification.
4. Handling Ambiguities
If a request conflicts with the specification, point out the conflict before implementing.
If a requirement is unclear, ask for clarification rather than making significant assumptions.
If a technical limitation prevents the specified implementation, explain the limitation and suggest alternatives.
5. Documentation

When implementation decisions change, update the relevant project documentation.

Keep the specification and actual implementation consistent.

6. General Rule

The project specification takes precedence over assumptions, generic coding conventions, and suggestions made by the AI.

Do not treat the specification as optional background information. It is the project's functional and technical contract.
